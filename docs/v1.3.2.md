# Vybe — Périmètre de la V1.3.2 : photos des villes

> Petite évolution après la refonte V1.3.1 : les tuiles « Villes » (Découvrir, Recherche) affichent une **vraie photo de chaque ville**, au lieu de la photo de test d’un artiste qui y joue.

## Fonctionnalités incluses

- **Photo par ville** pour les 11 villes de démonstration, choisie sur **Wikimedia Commons** (licences libres : domaine public, CC BY, CC BY-SA), vérifiée une par une (pas de montage, sujet reconnaissable).
- **Stockage dans Supabase Storage** (bucket public `city-images`) : l’app ne charge aucune image depuis un site externe (règle 2) ; Wikimedia refuse d’ailleurs les images aux clients Android par défaut.
- **Secours** : une ville sans photo garde la photo d’un artiste qui y joue (comportement de la V1.3.1).
- **Crédits photos** dans la page Infos (auteur · licence, lien vers la page d’origine), obligatoires pour les licences CC BY / CC BY-SA.

## Données et technique

- Migration `city_images` : colonnes `cities.image_path`, `image_credit`, `image_source_url` ; création du bucket public `city-images` (JPEG, 1 Mo max). Catalogue toujours en lecture seule (RLS inchangée, aucune écriture Storage depuis l’app).
- Fichiers sources : `supabase/seed-assets/city-images/*.jpg` (960 px de large) ; envoi avec `npx supabase storage cp` (voir README).
- `seed.sql` renseigne chemin, crédit et page d’origine de chaque photo.
- App : `src/lib/cityImages.ts` (URL publique d’une photo), `getCityPhotos` (photo de ville, sinon d’artiste), `src/features/infos/api.ts` (crédits).
- Aucune donnée personnelle, aucune nouvelle dépendance.
