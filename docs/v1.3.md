# Vybe — Périmètre de la V1.3 : compte et favoris

Référence : sections 12.4, 3.1, 3.6 et 10 du cahier des charges (`docs/cahier-des-charges.md`).

> **Ordre des versions** (décision du porteur) : V1.0 → V1.2 → **V1.3** ; la V1.1 (données réelles Ticketmaster) est faite plus tard. L’application fonctionne toujours sur les **données de démonstration**.

## Objectif

Permettre de **suivre, enregistrer et personnaliser** avec un compte, tout en gardant l’application consultable sans compte. Première version qui traite des **données personnelles** : RGPD complet pour les comptes.

## Fonctionnalités incluses

- **Compte par e-mail, sans mot de passe** : saisie de l’e-mail, réception d’un **code à 6 chiffres**, saisie du code. Connexion = inscription si le compte n’existe pas. Session conservée entre deux lancements ; déconnexion depuis le Profil.
- **Consultation sans compte** : tout le catalogue reste accessible. Le compte n’est demandé qu’au moment de suivre, d’enregistrer ou de personnaliser (invitation à se connecter, sans blocage).
- **Suivi d’artistes** : bouton « Suivre » sur la fiche artiste ; onglet **Mes artistes** (artistes suivis et leurs concerts à venir).
- **Onboarding court** après la première connexion : « Suis quelques artistes », à partir des artistes rap du catalogue (facultatif, passable).
- **Liste d’envies** : bouton ♡ sur la fiche concert ; onglet **Envies** (concerts à venir enregistrés, puis passés). Stockée dans la table unique `user_events` (statut `wishlist` ; `going` et `attended` prévus pour la V1.5).
- **Favoris et préférences** (Profil) :
  - **villes favorites**, dont une **ville principale** qui alimente automatiquement « Près de chez toi » une fois connecté ;
  - **salles favorites** : bouton sur la fiche salle, liste dans le Profil ;
  - **genres préférés** : enregistrés et affichés (recommandations prévues en V2.2).
- **Profil** : e-mail, préférences, confidentialité, **Exporter mes données**, **Supprimer mon compte**, déconnexion.

## Navigation

Cinq onglets (cahier des charges, section 4) : **Découvrir**, **Recherche**, **Mes artistes**, **Envies**, **Profil**. Les fiches (concert, artiste, salle), l’écran « Concerts » et la page Infos s’ouvrent depuis chaque onglet. Sans compte, Mes artistes et Envies affichent une invitation à se connecter.

## Données personnelles et RGPD (cahier des charges 10.1 à 10.4, 10.8)

- **Données traitées** : adresse e-mail (compte), artistes suivis, envies, villes et salles favorites, genres préférés. Toujours **aucun** outil d’analyse ni de suivi des plantages ; la localisation reste ponctuelle et jamais enregistrée (V1.2).
- **Finalités** : faire fonctionner le compte, le suivi, la liste d’envies et la personnalisation.
- **Conservation** : tant que le compte existe ; **suppression immédiate et complète** à la suppression du compte.
- **Droits** :
  - accès et portabilité : **Exporter mes données** (fichier lisible partagé par le menu de partage du téléphone) ;
  - rectification : modification des préférences dans le Profil ;
  - effacement : **Supprimer mon compte** depuis l’application (fonction SQL `delete_my_account()`, qui ne peut supprimer que le compte connecté ; toutes les données suivent en cascade) ;
  - opposition, limitation, questions : contact `vybe.infos@gmail.com`.
- **Information au bon moment** : courte mention sur l’écran de connexion, avec lien vers la politique de confidentialité.
- **Sécurité** : Row Level Security sur toutes les tables ; chaque utilisateur ne lit et n’écrit **que ses propres lignes** ; le catalogue reste en lecture seule. Aucune clé secrète dans l’application.
- Politique de confidentialité réécrite (Infos), à faire relire avant toute diffusion publique.

## Données et technique

- Authentification Supabase (e-mail + code à usage unique). Modèle d’e-mail Supabase à adapter pour afficher le code (action du porteur dans le tableau de bord).
- Session stockée avec le stockage local Expo déjà installé (`expo-sqlite/kv-store`).
- Nouvelles tables (migration) : `user_events`, artistes suivis, salles favorites, villes favorites (ville principale), genres préférés ; fonction `delete_my_account()`.
- Aucune nouvelle dépendance prévue (partage via l’API `Share` de React Native).

## Points de vigilance

- **Envoi des e-mails** : le service intégré de Supabase est très limité (débit, destinataires). Suffisant pour les tests du porteur ; un fournisseur d’e-mails dédié sera nécessaire **avant toute diffusion**.
- Connexion Apple et Google : au moment de la publication sur les stores (hors V1.3).
