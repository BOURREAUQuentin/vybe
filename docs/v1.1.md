# Vybe — Périmètre de la V1.1 : données réelles Ticketmaster

Référence : sections 7.1 et 12.2 du cahier des charges (`docs/cahier-des-charges.md`).

> **Ordre des versions** : V1.0 → V1.2 → V1.3 (+ 1.3.1 à 1.3.3) → **V1.1**. La V1.1 arrive après les comptes : la synchronisation devra donc préserver les envies et les artistes suivis des utilisateurs.

## Objectif

Remplacer les données factices par le **catalogue réel des concerts en France** issu de la Discovery API de Ticketmaster, importé par un **traitement serveur planifié**, en respectant les quotas, la conservation des données et l’attribution. L’application ne change presque pas : elle lit toujours uniquement Supabase (règle 2).

## Fonctionnalités incluses

- **Import planifié** (Supabase Edge Function `sync-ticketmaster`, lancée chaque nuit par une tâche planifiée) : concerts de musique en France sur les **6 prochains mois**, découpés par tranches de dates (pagination < 1000), 2 appels/s maximum.
- **Écriture en base** par identifiant stable (`source = 'ticketmaster'`, `external_id`) : création ou mise à jour des **événements**, **artistes** (attractions), **salles** et **villes** ; mise à jour des changements de date, de salle, de statut, de prix.
- **Statuts** : `onsale` → Billetterie ouverte, `canceled` → Annulé, `postponed` → Reporté, `rescheduled` → nouvelle date ; `offsale` → Annoncé si la vente n’a pas commencé, sinon Complet (règle à confirmer sur les données réelles).
- **Genres** : correspondance des genres Ticketmaster (*Hip-Hop/Rap*, *R&B*, *Pop*, *Dance/Electronic*, *French*…) vers les genres de Vybe ; un genre inconnu reste vide plutôt que faux.
- **Festivals** : enregistrés avec le type `festival`, non affichés (V2.3).
- **Images** : photo de l’événement et de l’artiste fournies par Ticketmaster.
- **Conservation** : événements passés marqués `past`, puis supprimés après 30 jours s’ils ne sont dans les envies d’aucun utilisateur ; événements qui disparaissent de Ticketmaster retirés de l’affichage.
- **Journal de synchronisation** consultable dans Supabase : début, fin, nombre d’appels, événements ajoutés / modifiés / retirés, erreurs.
- **App** : bouton « Billetterie officielle » et mention « Source : Ticketmaster » sur la fiche concert ; Découvrir adapté à un catalogue de plusieurs milliers de concerts (requêtes ciblées au lieu des 100 prochains concerts) ; page Infos (source des données, crédits).
- **Données de démonstration** conservées pour le développement (voir décision n° 2).

## Sécurité

- **Clé API Ticketmaster** : uniquement dans les secrets Supabase de la fonction (`supabase secrets set`), jamais dans l’app, `.env` ni Git.
- La fonction écrit avec les droits serveur ; l’app garde un accès en **lecture seule** au catalogue (RLS inchangée).
- La tâche planifiée appelle la fonction avec un secret partagé stocké dans le coffre de Supabase (Vault), jamais dans le code.
- Le journal de synchronisation n’est pas lisible depuis l’app.

## Décisions à valider

1. **Images** : afficher les images **depuis les adresses Ticketmaster** (prévu par l’API, aucune copie). Exception assumée à la règle « images du catalogue dans Storage » (V1.3.2), limitée aux images fournies par une source officielle qui les héberge elle-même.
2. **Données de démo** : une fois l’import validé, **masquer** les concerts de démonstration (`is_hidden`) plutôt que les supprimer — l’app n’affiche que du réel, et la démo peut être réaffichée pour le développement. Les envies existantes sur des concerts de démo disparaissent de l’affichage.
3. **Périmètre de l’import** : toute la musique en France sur 6 mois (et pas seulement le rap) : les filtres par genre et « Près de chez toi » ont besoin du catalogue complet ; le rap reste mis en avant dans Découvrir.

## Ordre de développement

1. Cadrage : ce document, compte développeur Ticketmaster, **appel de test** (couverture France, prix, genres).
2. Base : migration (journal de synchronisation, index et contraintes d’import, table de correspondance des genres).
3. Fonction `sync-ticketmaster` : récupération par tranches, transformation, écriture ; lancement manuel et vérification en base.
4. Mises à jour, statuts, conservation (purge), festivals.
5. Planification quotidienne (tâche planifiée + secret partagé).
6. App : fiche concert (Billetterie officielle, source), Découvrir sur un vrai catalogue, Infos ; masquage de la démo.
7. Suivi sur plusieurs jours, finitions, documentation, tag `v1.1`.
